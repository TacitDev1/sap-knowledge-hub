# OSU-207 Hard stop for POs without a cost centre

**Client:** Osterby Utilities · **Status:** In progress · **Systems:** BD1 → BQ1

## Ask
Finance wanted purchase orders of type `ZNB` to be impossible to save without a cost centre on every account assignment line. A warning was not enough.

## What was built
An implementation of [[ME_PROCESS_PO_CUST]], method `CHECK`:
- returns at once unless the order type is `ZNB`, so no other process is touched;
- loops over items and their account assignments;
- raises an error from the project's message class and sets `CH_FAILED` when a cost centre is missing.

Because `BAPI_PO_CREATE1` runs the same BAdI, purchase orders created by interfaces get the same check for free. That was a deliberate choice, explained in [[enhancement-framework]].

## Testing
Three scenarios from the spec in BD1: no cost centre (blocked), cost centre on some lines only (blocked, item named in the message), all lines filled (saves). Signed off by the client's finance lead.
