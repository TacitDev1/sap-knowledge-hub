# BRW-112 Bin orders uploaded from a spreadsheet

**Client:** Brackenfield Waste · **Status:** In progress · **Systems:** BD1 → BQ1 → BP1

## Ask
The route planners keep bin delivery orders in a spreadsheet and typed each one into VA01. They wanted a one-click upload.

## What was built
A report that reads the tab-separated file, groups rows into orders and calls [[BAPI_SALESORDER_CREATEFROMDAT2]] per order. It has a **test mode** (on by default) that runs every check without saving, and it shows the outcome per order in a [[CL_SALV_TABLE]] grid.

## What went wrong first
The first test run in BQ1 rejected every order with "sold-to party not maintained". The file used the partner role codes as they appear on an English screen. The BAPI wants the internal codes `AG` (sold-to) and `WE` (ship-to). After mapping them, 398 of 400 test orders went through; the two failures were customers correctly blocked for sales.

## Decisions
- One LUW per order, so a bad row never blocks the rest. See [[bapi-luw]].
- Commit with `WAIT` because the grid reads the order back: [[BAPI_TRANSACTION_COMMIT]].

## Still open
Final file from the planners, then transport to BP1.
