# BRW-124 Order IDocs stuck after a go-live

**Client:** Brackenfield Waste · **Status:** In progress · **Priority:** Highest

## Symptom
About 120 inbound ORDERS IDocs sat in status 51 after a new route-planning system went live on a Friday evening. No sales orders were created over the weekend.

## Diagnosis
Every failed IDoc had the same status text, which pointed at the processing function rather than at data. In WE20 the new sender's partner profile still used the inbound process code of the old system, which expects a different segment layout. Background on statuses and process codes: [[idoc-basics]].

## Fix
1. Corrected the process code in the BQ1 partner profile.
2. Copied three failed IDocs with WE19 and processed the copies. All posted and created orders through the same path as [[BAPI_SALESORDER_CREATEFROMDAT2]].
3. Raised a change for BP1, then mass-reprocessing with BD87.

## Lesson
Partner profiles are part of a go-live checklist, not an afterthought. Added a line to the release checklist in the [[log]].
