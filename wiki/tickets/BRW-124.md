# BRW-124 Driver app: 403, then every depot

**Client:** Brackenfield Waste · **Status:** In progress · **Systems:** BD1 → BQ1 → BP1

## Ask
The drivers' tablet app stopped loading stops after the new app version was deployed. Every call failed with 403 Forbidden.

## Three problems, one after the other
**1. 403 on every call.** The new app version used a renamed OData service. The drivers' role still had the old service under "Authorization Default", so [[S_SERVICE]] held the old hash. `/IWFND/ERROR_LOG` showed the failed check within a minute. Added the new service (`IWSG`, version `_0001`) to the role, merged and generated.

**2. 403 on confirming a stop only.** Reading worked; posting a confirmation failed. Not authorization: the CSRF token fetched on the first call was rejected because the new reverse proxy did not pass the session cookie through. Handed to the proxy team with the trace from `/IWFND/TRACES`.

**3. Every driver saw every depot.** With the calls working, a driver from depot 2100 saw stops for all depots. The service reads a CDS view that had no access control, so nothing filtered the rows. Added an access control with `aspect pfcg_auth( M_MSEG_WWA, WERKS, ACTVT = '03' )`, so the plant values already in the drivers' roles now drive the app as well.

## Decisions
- Reuse the existing plant object rather than a new custom one: one set of values per depot, no second thing to keep in step. See [[gateway-odata-security]].
- Test with a driver test user, never an admin user: the admin user saw every depot before and after, which is how problem 3 got past the first test.

## Still open
Proxy fix for the CSRF cookie; access control in BQ1 awaiting the depot test.
